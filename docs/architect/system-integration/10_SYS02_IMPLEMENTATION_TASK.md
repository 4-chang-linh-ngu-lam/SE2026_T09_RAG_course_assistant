# SYS-02 — Service JWT Foundation
Trạng thái: READY FOR IMPLEMENTATION sau khi đồng bộ Design Correction và đóng CORE-00. Không triển khai CORE-04 trong task này.
## Contract kỹ thuật đề xuất cho review
Ưu tiên thư viện JWT hiện có nếu an toàn. Service token tách biệt user token bằng issuer, audience, token type và key riêng; allowlist thuật toán asymmetric RS256; sub là service identity, aud là service đích, scope tối thiểu, iat/exp, kid; TTL đề xuất 5 phút, clock skew tối đa 30 giây. Không dùng user JWT cho internal API. Không lưu private key trong repo/log; cấu hình key qua secret mount/env reference; hỗ trợ nhiều public key theo kid để rotation. Mỗi service chỉ giữ signing key của mình; verifier trust map ràng buộc issuer/sub/key và audience/scope. Không dùng shared signing key toàn hệ thống. Không tạo token issuer HTTP mới nếu không cần. Các giá trị này là đề xuất kỹ thuật, cần đối chiếu discovery trước khi freeze; nếu xung đột thì báo TL.
## Phạm vi
Shared signing/verification contract, Core integration dependency, config examples không chứa secret, tests và tài liệu sử dụng. Legacy X-Service-Key chỉ giữ trên route cũ với chính sách hiện tại, không fallback khi JWT sai, không cho route mới dùng legacy. Không sửa user auth, business authorization, schema hoặc gateway ngoài phạm vi.
## Gate
Test valid token, wrong issuer/aud/scope/type/key/algorithm, expired/future/malformed, missing token, user token, spoofed identity, rotation, legacy isolation, regression. Không log token. Local test nhẹ; full suite/Docker/integration trên Testing server qua SSH đã xác minh fingerprint; không Production, không bypass host key. Nếu server chưa sẵn sàng ghi BLOCKED, không báo verified. Không commit/push/PR/merge/deploy nếu chưa duyệt riêng. Báo diff, commands, exit codes, test evidence và blockers.
